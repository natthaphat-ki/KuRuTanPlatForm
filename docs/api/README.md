# API Documentation (Phase 2 — FastAPI Core, Phase 3 — Report & Evidence business rules)

Interactive, always-up-to-date API docs are generated by FastAPI itself:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- Raw OpenAPI schema: `http://localhost:8000/openapi.json`

## Base URL

All versioned routes are mounted under `API_V1_PREFIX` (default `/api/v1`),
configured in [`app/core/config.py`](/services/api/app/core/config.py).

## Report Lifecycle

```
[User Submit] -> UNVERIFIED --(Duplicate Check via reference_key)-->
   -- POST /reports/{id}/submit-for-review (needs >=1 image Evidence) -->
PENDING_REVIEW -- POST /reports/{id}/review {decision, discredit_factor_id} -->
   VERIFIED (DiscreditLedger entry created, score recalculated)
   REJECTED (no score impact)
```

`UNVERIFIED` reports are shown in the Public View but never affect a
Seller's Discredit Score (Presumption of Innocence Rule).

## Evidence Upload (Phase 3 — local disk storage backend)

```
POST /evidence/upload  (multipart/form-data: report_id, file, comment?)
   -> validates file extension against a whitelist (image/document/video/audio)
   -> streams to disk under storage/evidence/<report_id>/<uuid><ext>,
      enforcing MAX_EVIDENCE_FILE_SIZE_BYTES (default 25 MB) while hashing
   -> SHA-256 file_hash is compared against every other Evidence row; a
      match sets duplicate_of_evidence_id (the "สลิปเดียวกัน" / same-slip
      duplicate check) without blocking the upload
GET /evidence/{id}/file
   -> streams the stored file back (FileResponse)
```

See [`app/core/storage.py`](/services/api/app/core/storage.py) for the
extension whitelist and streaming/hashing implementation, and
[`app/services/evidence_service.py`](/services/api/app/services/evidence_service.py)
for the duplicate-detection + audit trail logic. Swapping this for an
S3/MinIO-backed store later only requires changing `storage.py`.

Legacy `POST /evidence` (JSON body with `file_url`) still exists for
registering evidence that is already hosted externally (e.g. a marketplace
screenshot link) rather than uploaded through this API.

## Dispute / Appeal Lifecycle

```
POST /disputes {report_id, seller_id, reason, counter_evidence}
   (only allowed while the Report is VERIFIED) -> Report becomes APPEALED
POST /disputes/{id}/resolve {decision: "approved" | "rejected"}
   approved -> Report VOIDED, DiscreditLedger entry flagged is_voided (never
               deleted -- Traceability Rule), Discredit Score recalculated
   rejected -> Report back to VERIFIED, score maintained
```

## Auth

- `POST /api/v1/auth/login` uses the OAuth2 **password** flow
  (`application/x-www-form-urlencoded`, fields `username` = email, `password`).
- Send the returned `access_token` as an `Authorization: Bearer <token>` header on
  subsequent requests.
- Roles: `public`, `user`, `admin`, `officer` (see
  [`app/core/permissions.py`](/services/api/app/core/permissions.py) for the
  `require_roles(...)` dependency used to guard routes).
